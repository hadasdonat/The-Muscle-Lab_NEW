# Deploying The Muscle Lab

This guide puts the app online with free tiers: the API and the React build on [Render](https://render.com/docs/free), the database on a hosted MySQL-compatible service, and the AI Coach on the Gemini API. Nothing here needs a credit card, but free tiers have limits, listed at the end.

```text
Browser ──> muscle-lab-web (Render static site, React build)
   │
   └──────> muscle-lab-api (Render web service, Express) ──> MySQL-compatible database (TLS)
                                                        └──> Gemini API (optional)
```

## 1. Create the database

The app needs MySQL 8 features (expression defaults such as `DEFAULT (UUID())`, `SELECT ... FOR UPDATE`).

**Free option: TiDB Cloud Starter.** It speaks the MySQL protocol, has a free monthly quota, and requires TLS. Create a Starter instance, open **Connect**, choose **General / Node.js**, and note the host, port (4000), user (it looks like `xxxxx.root`) and password. TiDB's certificate is publicly trusted, so `DB_SSL=true` is enough and `DB_SSL_CA` stays empty.

TiDB is MySQL-compatible, not identical. The app's tests run against MySQL 8, so after setup run the smoke test in step 5. If schema setup fails on TiDB, use a hosted MySQL 8 instance instead (for example Aiven's Developer plan or Railway; both are paid, around $5 a month). For a provider whose CA is not publicly trusted, paste its CA certificate into `DB_SSL_CA`.

## 2. Load the schema and demo data

Run these once from your computer, with the hosted database's details in your shell (not committed anywhere):

```bash
cd server
export DB_HOST=<host> DB_PORT=<port> DB_USER=<user> DB_PASSWORD='<password>' DB_SSL=true
DB_NAME=muscle_lab npm run db:setup
DB_NAME=muscle_lab DEMO_PASSWORD='<a demo password you will publish>' npm run db:demo
```

`db:setup` creates the database and tables and refuses to touch an existing database. `db:demo` adds three trainers, ten members, five weeks of classes around today, bookings and attendance, and two public demo logins:

| Role | Email |
| --- | --- |
| Member | `member@musclelab.demo` |
| Trainer | `trainer@musclelab.demo` |

Both use `DEMO_PASSWORD`. Anyone with the link can sign in with them, so they only hold synthetic data. `db:setup` also inserts the local seed accounts, whose password is published in the README. Before going public, delete or re-password `demo-admin@example.com`, `demo-trainer@example.com`, `demo-member-one@example.com` and `demo-member-two@example.com`. Create your own Admin with a private password if you need one.

Demo classes are dated relative to the day you run `db:demo`. Re-run it on a fresh database (new `DB_NAME`) when the schedule gets old.

**Without a terminal:** create an empty database (for example `CREATE DATABASE muscle_lab;` in the provider's SQL console), set `DEMO_PASSWORD` on the API service, and use the start command `npm run start:hosted`. On its first start the API creates the tables, roles, plans and demo data. On every start it applies pending migrations and tops up the demo schedule, so there are always classes for the next two weeks; nothing is duplicated.

## 3. Get an AI key (optional)

Create a Gemini API key in [Google AI Studio](https://aistudio.google.com/apikey). Keep it out of the repository and out of chat messages; it only goes into the API service's settings on Render. Without a key, the coach uses its rule-based ranking and labels itself "Based on your history".

To use another provider, set `AI_PROVIDER=openai` with `AI_BASE_URL` for any OpenAI-compatible API (OpenAI, Groq, OpenRouter, a local Ollama), or `AI_PROVIDER=anthropic`. `AI_MODEL` overrides the default model.

## 4. Deploy on Render

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint** and select the repository. Render reads [`render.yaml`](../render.yaml) and proposes two services.
3. Fill in the values it asks for:
   - **muscle-lab-api**: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` (for example `muscle_lab`), `AI_API_KEY`, and `CORS_ORIGINS`. Leave `CORS_ORIGINS` as a placeholder for now.
   - **muscle-lab-web**: `VITE_API_URL`. Leave a placeholder for now.
4. After the first deploy, copy the two service URLs and set:
   - `VITE_API_URL` on **muscle-lab-web** to the API URL, for example `https://muscle-lab-api.onrender.com` (no `/api`, no trailing slash). Redeploy the static site, because Vite reads this value at build time.
   - `CORS_ORIGINS` on **muscle-lab-api** to the static site URL, for example `https://muscle-lab-web.onrender.com`. The API restarts on its own.

`JWT_SECRET` is generated by Render. `TRUST_PROXY=1` lets the login rate limit see each visitor's own IP instead of Render's proxy; if login throttling ever seems to hit everyone at once, the hop count is wrong; see express-rate-limit's documentation on proxies. `TZ=Asia/Jerusalem` makes "now" match the gym's local class times; change it if the gym is elsewhere.

## 5. Smoke test

1. Open `https://<api>/api/health`. It should return `{"status":"ok"}`. The first request after a quiet period can take about a minute while the free instance wakes up.
2. Sign in as the demo member. The dashboard's AI Coach card should say "Powered by Gemini" and suggest a class you can register for.
3. Sign in as the demo trainer. The attendance page lists Dana's classes; the last two days are left unrecorded on purpose.
4. Check the Render logs for `Coach:` warnings. They mean the model call failed (wrong key, quota, model name) and the coach fell back to rules.

## Free-tier limits

- The free Render web service sleeps after 15 minutes without traffic and wakes on the next request.
- Render's disk is not persistent on the free plan, so uploaded profile photos disappear on redeploys and restarts.
- Rate limits are kept in memory, per instance.
- The Gemini free tier has a request quota. The coach caches each member's suggestion for 10 minutes and allows 6 requests per member per minute.
